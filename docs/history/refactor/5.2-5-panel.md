# 5.2-5 `ui::Panel` / `PanelResult` / `PanelState`

对应 `ARCH-REVIEW.md` F3 的 ui 部分与 F4 的 ui 部分。分片落地。

## A 片（已落地）：`PanelState` 去 `Cell`

`PanelState` 里 12 个 `Cell`/`RefCell` 存在的唯一理由是 `frame_view(&self)` 用共享借用组装整帧，而渲染要写回滚动夹紧结果、行预算、光标目标、picker 缓存。这不是 Go 的镜像，是用内部可变性绕借用检查，比 Go 原版更难读。

```rust
// 渲染拿 &mut，把光标目标作为结果带出来，而不是塞进 Cell 供事后读取
pub(crate) struct Rendered { rows: Vec<String>, cursor: Option<(u16, u16)> }
pub(crate) fn render_surface(st: &mut SurfaceState, panels: &[Panel], width: u16) -> Rendered;
// SurfaceState::cur 与 cursor_target() 消失；term_h 变普通字段，set_term_height 拿 &mut self
// PanelState：offset / wrapped / rows / input_offset / pending_center / wrap_starts / preview 全部变普通字段
// picker 的 prev_idx / prev_cols / prev_rows / prev_valid / prev_cache 收成 Option<PreviewCache>
// SearchState::input_offset 同样变普通字段；field::input_field 收 &mut usize
```

连锁：`Model::frame_view(&mut self)`；`oneshot::run_surface` 用返回的 `cursor`；各渲染函数把 `st: &SurfaceState` 参数换成真正需要的东西（`cursor: &mut Option<_>` 或 `term_h: usize`），因为 `ps` 已经是 `st.ps` 的可变借用。

行为边界：无。字节输出不变；测试夹具的 `content(&self)` 变 `&mut self`。

## B 片（已落地）：`Panel` 改 enum body

```rust
pub struct Panel { title, prompt, search, height, refresh: Option<RefreshFn>, body: PanelBody }
pub enum PanelBody {
    List(ListBody), Multi(ListBody),           // items, cursor, checked, custom, details
    Slider(SliderBody),                        // min, max, step, value
    Switch { on: bool },
    Input(InputBody),                          // text, placeholder, width
    Browser { dir: PathBuf },
    Picker(PickerBody),                        // items, cursor, details, preview
    View(ViewBody),                            // lines, wrap
}
```

- 构造器 `Panel::list / multi / picker / slider / switch / input / view / browser / of(title, body)`，builder `with_prompt / with_search / with_height / with_refresh / with_cursor / with_checked / with_custom / with_details / with_wrap / with_input_width / with_preview / with_on`（对不相干的 kind 是 no-op），读取点走 `kind() / items() / cursor() / checked() / custom() / details() / lines() / wrap() / as_slider() / on() / as_input() / dir() / has_preview() / take_preview()`。`PanelKind` 保留为 `kind()` 推导出来的标签：渲染分发、hint 表、`PanelSummary` 和测试表格按标签匹配比按 body 解构更短，84 处非测试 `PanelKind::` 因此留下；只有需要拿字段的地方（`PanelState::for_panel`、slider 步进、input 渲染等 19 处）才 `match &p.body`。
- 与设计的三处偏离：`refresh` 放在 `Panel` 上而不是 `View` 里（tabbed 的 `r` 键对任何 kind 都走它）；`search` / `height` / `prompt` 同理是公共字段；`PanelResult` 保持扁平——它是一次性回传，调用方按自己开的 kind 读对应字段，改成 enum 只会让每个调用点多一层解构而不会挡住任何错误。
- `PanelBody::empty(kind)` 供夹具按表驱动生成各 kind 的空面板；`clone_shape` 测试助手改为按 body 复制形状字段。

### 迁移过程记录

- 75 处字面量由括号感知的转换器改写成构造器 + builder 链；74 处 `.x` → `.x()` 由 `E0615` 驱动的循环完成；`E0609`（slider / input 专属字段）映射到 `as_slider().map_or(..)` / `as_input().map_or(..)`。
- 两个坑：`E0609` 循环对同一行里多次出现的 slider 字段会嵌套替换（`p.as_slider().map_or(0.0, |s| s.as_slider()…)`），`render_slider` / `slider_step` 最终手写成先 `let Some(sl) = p.as_slider()` 再用 `sl.min/max/step`；没有 `..Panel::default()` 底的全量字面量在第二遍才被覆盖，转换器把尾巴留在原地，三处手修。
- 行为边界：无。字节输出不变，1404 项测试与跨二进制往返照旧通过。

## C 片（已落地）：`SurfaceState` 拥有面板

```rust
pub(crate) struct PanelSlot { pub(crate) spec: Panel, pub(crate) state: PanelState }
pub(crate) struct SurfaceState { focus, enter_advances, slots: Vec<PanelSlot>, term_h }
impl SurfaceState {
    pub(crate) fn new(enter_advances: bool, panels: Vec<Panel>) -> Self;   // 拿走所有权
    pub(crate) fn focused(&mut self) -> (&Panel, &mut PanelState);         // slots[focus] 的拆分借用
    pub(crate) fn key(&mut self, KeyEvent) -> SurfaceEffect;               // 原 surface_key(st, panels, key)
    pub(crate) fn render(&mut self, width) -> Rendered;                    // 原 render_surface(st, panels, width)
    pub(crate) fn tick(&mut self);                                         // 原 tick(st, panels)
    pub(crate) fn paste(&mut self, &str);                                  // 原 paste(st, panels, data)
    pub(crate) fn result(&self) -> TabbedResult;  set_focus(&mut self, i);
}
```

- 原来 `SurfaceState.ps: Vec<PanelState>` 与调用方手里的 `Vec<Panel>` 平行下标，十二个函数都带着 `(st, panels)` 两个参数、内部再各自 `panels[focus]` / `st.ps[focus]`；持有者（`event_loop::SurfaceOpen`、`oneshot::run_surface`、七个测试夹具）各自保存两份。现在 spec 与 state 是同一个 `PanelSlot` 的两个字段，`focused()` 一次拆借出 `(&Panel, &mut PanelState)`，借用检查自然放行；键梯的私有函数只收 `st: &mut SurfaceState`，四个入口变方法。
- `new` 拿走 `Vec<Panel>` 所有权后，Picker 的 preview 闭包从 spec 挪进 state 这件事收在 `PanelSlot::open` 里，两处 `NEEDS [WP64]` 注释（“为什么 `&mut panels`”）随之消失。
- `enter_commit` / `editor_key` 先把 `enter_advances` 与 `slots.len()` 拷出来再取 `focused()`，避免 `set_focus` 时借用冲突——这是唯一需要注意的形状。
- 行为边界：无。测试夹具从 `Surf { st, panels }` 变 `Surf { st }`，`s.panels[i]` 读法改 `s.st.slots[i].spec`。
