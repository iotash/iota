# 5.2-7 `cmd` 的 `Startup` 拆分（F4 cmd 部分）

现状：`cmd::run()` 是 290 行的一条直线，末尾把 16 个局部变量装进 `interactive::Startup<'a>` 交给 `run_interactive(mut s)`；后者再把 `&mut s` 交给 `wire_session`，它读其中 9 个字段并 `mem::take` 两个（`mcp_configs`、`mcp_defers`）——读者看不出哪一步依赖什么、哪个字段在哪一步被消费。

## 形状

```rust
/// 整个进程共享、只读的运行环境（-m 与交互两条分支都用）。
#[derive(Clone)]
pub(crate) struct RunContext {
    pub dirs: HostDirs,
    pub http: reqwest::Client,          // MCP 传输拿裸客户端
    pub transport: HttpTransport,       // provider / title 实例 / 子 agent 走带 /debug 记录的
    pub reqlog: Arc<RequestLog>,
    pub resolver: Arc<dyn VarResolver>,
    pub cancel: CancellationToken,
}

/// root.go:187-241 装配出来的工具侧：一次构造，两条分支各自消费。
pub(crate) struct ToolAssembly {
    pub mcp_configs: Vec<ServerConfig>,
    pub mcp_defers: Vec<DeferredGroup>,
    pub tool_env: Env,
    pub interactor: Option<Arc<Interactor>>,   // 只有交互分支创建
    pub delegator: Option<Arc<ChatDelegator>>,
    pub agent: AgentOptions,
}

/// 交互分支的入参：六项，每项都是一个阶段的产物。
pub(crate) struct Interactive<'a> {
    pub cli: &'a Cli,
    pub settings: RunSettings,
    pub kind: ProviderKind,
    pub provider: Box<dyn Provider>,
    pub ctx: RunContext,
    pub tools: ToolAssembly,
}
```

`run()` 提成具名阶段（顺序即 root.go 的顺序，每个阶段的 byte-pinned 错误位置不变）：

1. `load_config` — 已有（`Config::load`）。
2. `resolve_run` — 已有。
3. `RunContext::new(dirs, cancel, env)` — http/reqlog/transport/resolver。
4. `open_provider(&settings, &ctx, io) -> (ProviderKind, Box<dyn Provider>)` — `new_provider` + `tuning::apply`。
5. `assemble_tools(&cli, &cfg, &settings, &*provider, &ctx, env, io) -> ToolAssembly` — MCP 配置、`warn_tools_without_calling`、agent 选项、tool env + interactor、delegator。
6. `output_format(&settings)` — `--output-format` 的解析与 `OutputFormatWithoutMessage`。
7. 分支：`run_headless(message, cli, settings, kind, provider, tools, ctx, format, io)` 或 `interactive::run_interactive(Interactive { .. }, io)`。

交互侧：`run_interactive` 开头把 `Interactive` 与 `ToolAssembly` 解构成局部变量，之后每个阶段只拿它需要的东西；`wire_session` 的签名变成显式依赖——`(cli, &settings, kind, &mut dyn Provider, &ctx, &tool_env, io, &store, scope, WireInput)`，`WireInput` 多带 `mcp_defers`（所有权移入，`mem::take` 消失）；`resolve_context_window(cli, &settings, &dyn Provider, session_window, io)`。

## 行为边界

- 无。所有告警/错误的顺序与文本不变；`open_ui` 的 §8.4 顺序法不变；测试 `open_ui_releases_the_picker_before_tui_start` 照旧。

## 落地记录

- `cmd::run()` 现在是：`Config::load` → `-l` → `resolve_run` → `RunContext::new` → `open_provider` → `assemble_tools` → 输出格式 → 分支（`interactive::run_interactive(Interactive { cli, settings, kind, provider, ctx, tools })` 或 `run_headless(...)`）。三个阶段函数各自带 root.go 行号注释，顺序与原来逐行一致。
- `Interactive` 六个字段取代 `Startup` 十六个；`run_interactive` 开头把它和 `ToolAssembly` 解构成局部变量，`mem::take` 两处消失。`wire_session(cli, &settings, kind, &mut dyn Provider, &ctx, &tool_env, io, &store, scope, WireInput { .., mcp_defers })`、`resolve_context_window(cli, &settings, &dyn Provider, session_window, io)`。
- 一处顺手的简化：`session_cwd` 原来按 `agent_mode` 在 `agent.root` 与 `dirs.cwd` 之间选，而 `scope` 在 agent 模式下就是 `agent.root`，于是改为 `scope.map_or_else(..)`，`wire_session` 不再需要 `agent`。
- 行为边界：无。`cargo test` 1390 通过；全量 CI 与 5.2-8A 合跑（结果记在 ARCH-REVIEW 进度行）。
- 全量 CI（`refactor/ci-52-78.log`，与 5.2-8A/5.2-7 合跑）通过：1404 测试，跨二进制往返 `raw_restored=1`。
