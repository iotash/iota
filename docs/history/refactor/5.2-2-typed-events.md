# 5.2-2 wire 层产出类型化事件（先 anthropic，后 openresponses）

对应 `ARCH-REVIEW.md` F2。目标：`type` 字符串的 `match` 只在 wire 层写一次，dialect 拿到穷尽的枚举；`BlockAcc.kind`、`stop_reason` 跟着变成枚举。会话文件不受影响——回放 blob 仍是 `Raw`。

## anthropic

```rust
// llm/anthropic.rs —— 对外只剩这些
pub(crate) enum AnthropicEvent {
    MessageStart { usage: Option<AnthropicUsage> },
    BlockStart { index: u32, kind: BlockKind, id: String, name: String, raw: Raw },
    Delta { index: u32, delta: DeltaKind },
    MessageDelta { stop_reason: Option<StopReason>, output_tokens: Option<u64> },
    Other,                                   // content_block_stop / message_stop / 未知
}
pub(crate) enum BlockKind  { Text, Thinking, RedactedThinking, ToolUse, ServerToolUse, ToolSearchToolResult, Other(String) }
pub(crate) enum DeltaKind  { Text(String), Thinking(String), InputJson(String), Signature(String), Other }
pub(crate) enum StopReason { EndTurn, MaxTokens, StopSequence, ToolUse, Other(String) }
pub(crate) enum RespBlock  { Text { text: String }, Other }     // #[serde(tag = "type")]，unary 路径
```

`RawEvent`/`RawDelta`/`ContentBlockStart` 变成模块私有的反序列化中间体；`AnthropicStream::next()` 做 `ping`/`error` 处理后调用 `RawEvent::classify()`。`content_block_start` 的两段解析（先拿 `Raw`，再从中读 `type/id/name`）也搬进 `classify()`——`Raw` 不能进 `#[serde(tag)]` 枚举，这是 F2 指出的诚实做法。

`BlockKind::of_raw(&Raw)` 替代 provider 里的 `Probe` 小结构体，供回放过滤用；`BlockKind::is_thinking()` 表达「无条件回放」的两种块。

provider 侧：事件循环变成对 `AnthropicEvent`/`DeltaKind` 的穷尽 `match`，`BlockAcc.kind: BlockKind`，`assemble` 对 `BlockKind` 穷尽匹配，`stop_reason: Option<StopReason>`。

## 行为边界

- 全部 wire 字节不变；集成测试是 SSE 文本驱动，无需改动。
- `message_delta` 的 `stop_reason`：以前是「最后一个带 `delta` 的事件赋值，空串也赋」，现在是 `Option`，空串即 `None`。唯一消费者只看它是否为 `tool_use`，真实流里 `message_delta` 恰好出现一次。
- 未知 delta 类型、未知事件类型继续被忽略（`DeltaKind::Other` / `AnthropicEvent::Other`），与 Go 一致。

## openresponses（已落地）

```rust
pub(crate) enum RespEvent {
    ReasoningDelta(String), TextDelta(String), ImageGenerating, ImagePartial(String),
    ItemAdded(Raw), ArgumentsDelta { item_id, delta }, ArgumentsDone { item_id, arguments },
    ItemDone(Raw), Completed(Option<RespResponse>), Other,
}
pub(crate) enum ItemKind { Message, Reasoning, FunctionCall, ImageGenerationCall, ToolSearchCall, Other(String) }
```

- 终止失败（`error` / `response.failed` / `response.incomplete`）仍在 `next()` 里转成 `LlmError::Failure`，不进枚举；`"error": null` 仍视为不存在。
- 无 `type` 但带 `delta` 的帧（某些中继）分类为 `TextDelta`，与旧的 `_ =>` 兜底一致。
- `RespOutputItem::kind()` / `RespOutput::kind()` / `ItemKind::of_raw(&Raw)` 替代 provider 里的 `TypePeek` 和三处 `r#type` 字面量比较；`on_item_done` 改为接收 `&Raw`（`None` 的分支已由 `RespEvent::Other` 吸收）。
- 内联测试里对 `failure()` 的用例改为反序列化私有的 `RawRespEvent`。
