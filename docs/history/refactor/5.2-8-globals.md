# 5.2-8 主题标志与进度 task-local 显式化（F13）

## A（已落地）：主题标志

两个 `static DARK_BACKGROUND: AtomicBool`（`ui::theme`、`repl::styles`）各有一个消费者：`input_bg()`（surface 渲染，事件循环线程）与 `diff_shades()` / `diff_code_theme()`（`render_diff`）。两边的调用方其实都已经拿着 `dark`——事件循环收到的是 `UiMsg::DarkBackground(dark)`，`Repl` 有 `dark` 字段——只是把它写进全局再从全局读回。

- `ui`：`Model.dark: bool`（`TuiOptions.dark` 起始，`UiMsg::DarkBackground` 更新），`SurfaceState.dark` 像 `term_h` 一样在每帧渲染前发布（`set_dark`），`render_rows` → `input_bg(dark)`；`oneshot::run_surface(spec, dark)` 拿 `open_ui` 已探测到的值（今天它读的是尚未设置的默认 `true`，行为上等价于「一次性 picker 总按深色渲染」——改成显式后 picker 会按真实探测值渲染，这是唯一的可见变化，且是修正）。`theme::set_dark_background` 与原子删除；`surface/tests.rs` 里为串行化原子而加的 `static BG: Mutex<()>` 一并删除。
- `repl`：`render_diff(.., dark: bool)`，`diff_shades(dark)` / `diff_code_theme(dark)`；`group.rs` 的 diff 行由持有 `dark` 的组件传入（组件每 turn 构造，`Repl.dark` 在 turn 之间刷新，与今天 `set_dark_background` 的刷新时机一致）。`styles::set_dark_background` 与原子删除。

## B：进度 task-local（不做，记录理由）

`TURN_PROGRESS` 只有两处 `scope`（`turn.rs` 的 round / 单发两条路径）和一处读取（`Client::send_payload`）。显式化意味着 `Provider` trait 的 `chat` / `chat_observed` / `stream_chat_with_tools` / `list_models` 与 11 个文件里 31 个 `cancel: &CancellationToken` 签名全部改成 `&RequestScope { cancel, progress }`，外加 tests/ 里每个 `chat(&cancel, ..)` 调用点。收益是消除「cancel 显式、进度环境值」的不对称；代价是整个 provider 面的签名改动。task-local 在这里是 Rust 处理「每 task 环境值」的常规手段，读取点与作用域点各只有一处，不构成可读性问题。结论：不改；若将来 `Provider` 签名因别的原因要动（例如把 `cancel` 收进请求上下文），届时一并带上 `progress`。

## 行为边界

- 除 picker 的一次性 surface 现在按真实背景色渲染输入框底色外，字节输出不变。

## 落地记录（A）

- `ui`：`theme::input_bg(dark)`；`SurfaceState.dark` 与 `term_h` 同样由循环在每帧前发布（`set_dark`），`render_list` / `render_input` 多收一个 `dark`；`Model.dark` 由 `UiMsg::DarkBackground` 更新，`Tui::start` 不再写全局，而是把探测到的色调作为循环的第一条消息发出去（`handle.set_dark_background(opts.dark)`）；`oneshot::run_surface(spec, dark)`，`TerminalSeam::run_surface` 同步加参，`open_ui` 把探测值传给 picker。`ui::theme` 与 `repl::styles` 的两个 `AtomicBool` 及 `set_dark_background` 删除；`surface/tests.rs` 的 `BG` 互斥锁删除。
- `repl`：`Transcript::Inner.dark` + `Transcript::set_dark`，`render_diff(.., dark)`、`diff_shades(dark)`、`diff_code_theme(dark)`；运行循环在建好 transcript 时和每轮 host 重探后各调一次 `tr.set_dark`，与原来 `set_dark_background` 的两处时机一一对应。
