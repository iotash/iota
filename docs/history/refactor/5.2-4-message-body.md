# 5.2-4 `Message` 改 sum type（已落地）

对应 `ARCH-REVIEW.md` F3 的 `Message` 部分。目标：角色专属字段不再摊平在一个 struct 上靠注释约束，而由类型保证「一个 Tool 消息不可能带 tool_calls」。

## 形状

```rust
pub struct Message {
    pub content: String,             // 每个角色都有文本（tools mount 为 ""）
    pub attachments: Vec<Attachment>,// 输入附件或生成的图片，任何角色
    pub body: Body,
}
pub enum Body {
    System,
    ToolsMount(Vec<ToolDef>),        // 原来的「System + 非空 tools + 空 content」隐式变体
    User,
    Assistant(AssistantBody),        // reasoning, tool_calls, raw_content, usage, interrupted
    Tool(ToolBody),                  // call_id, call_name, is_error
}
```

`Role` 枚举保留（wire 与会话记录的 `role` 字符串仍由它映射），`Message::role()` 从 `body` 推导。

## 迁移策略（报告建议的顺序）

- 构造器签名不变：`system` / `user` / `assistant` / `assistant_with_calls` / `tool_result` / `system_tools`；新增 `assistant_body(content, AssistantBody)`、`tool_reply(call_id, call_name, text, is_error)`、`of_role(role, content)`（测试助手用）以及 `with_usage` / `with_reasoning` / `with_tool_calls` / `with_raw_content` / `with_interrupted` / `with_error` 六个 builder，承接原来 `Message { usage, ..Message::assistant(..) }` 这类「构造器为底再补字段」的写法；对错误角色它们是 no-op。`system_tools(vec![])` 与旧语义一致，得到普通 `System`（原 `is_tools_mount` 要求 tools 非空）。
- 读取点改 accessor：`role()`、`reasoning()`、`tool_calls()`、`raw_content()`、`usage()`、`interrupted()`、`is_error()`、`tool_call_id()`、`tool_call_name()`、`tools()`；写入点走 `as_assistant_mut()` / `as_tool_mut()`（accessor 用 `as_` 前缀，避免与同名构造器冲突）。
- `content` 与 `attachments` 的读写点（占绝大多数）不受影响。
- 会话文件：`SessionRecord` 不动，`record_to_message` / `to_record` 按 `body` 匹配；golden 与跨二进制往返测试验证字节不变。

## 行为边界

- 无。全部是形状变化；`PartialEq`/`Default`/`Clone` 派生照旧（`Default` = `User`，与原 `Role::default()` 一致）。
- 一条会话记录若 `role` 为 assistant 却带 `tool_call_id`（旧文件里不会出现）：loader 只按角色取对应字段，其余忽略——与原来「字段虽在但无人读」等价。

## 迁移过程记录

- 三个自动化步骤：括号感知的字面量转换器（先处理常量 `role:`，再处理任意底表达式加角色专属字段），编译器 `E0615`（"method, not a field"）驱动的 `.x` → `.x()` 修复循环，以及跨行 `assert_eq!` 里 `raw_content()` 的 `.cloned()` 补丁。
- 两个教训：转换器最初把 `fn user() -> Message {` 的函数签名当成字面量，吞掉整个函数体；去冗余字段名的正则不能不锚定整行，否则 `content: content.into()` 被误伤。脚本不可重入——重跑一次把 builder 插了两遍。都被编译器拦下，无残留。
- `src/repl/tokens.rs` 有一条测试给 User 消息塞了 `reasoning`，新模型下不可能，改为 Assistant，计数期望不变。
