# 5.2-3 repl 的 turn 状态与返回值

对应 `ARCH-REVIEW.md` F4（repl 部分）与 F5。分两片落地，第三片（自由函数改成 `TurnEngine` 方法）单独评估。

## A 片（已落地）：Go 多返回值 → 具名类型（F5）

```rust
// repl/turn.rs
pub(crate) struct RoundOutcome { result: Result<RoundResult, ChatError>, partial: String, partial_reasoning: String }
pub(crate) struct TurnReport {
    outcome: Result<TurnOutput, TurnFailure>,   // TurnOutput 不再背 used_tools / side_fx
    used_tools: bool, side_fx: u32,
    partial: String, partial_reasoning: String, // 只有用户打断时非空（Go fail() 的语义不变）
}
// repl/interrupt.rs
pub struct InterruptDecision { history: Vec<Message>, persist: bool, dropped_attachments: Vec<Attachment> }
// repl/commands/settings.rs
pub(crate) struct Rows<T> { values: Vec<T>, labels: Vec<String>, cursor: usize }
// chat/run.rs：unary 分支也产出 LoopOutcome，最终 assistant 消息只写一次
```

`run_turn` 返回 `TurnReport`；`tool_loop` / `stream_turn` 直接组装 `TurnReport`（`success` / `failed` / `bare` 三个构造器），`walk` 返回 `Result<(), TurnFailure>`，`run_turn` 末尾只填一次 `used_tools`。`TurnError` 消失。

行为边界：无。全部是形状变化；tests/repl/interrupt.rs 的 9 处元组解构和 toolloop 测试桩对 `err.partial` 等字段的断言改为读 `report.*`。

## B 片（已落地）：turn 相关状态收进 `Repl`（F4 的低风险部分）

`run()` 的栈变量 `gate`、`images_dir`、`image_provider`、`dark`、`overlay`、`agent`、`title_provider`、`title_task`、`compact_declined` 变成 `Repl` 字段（`token_aware` 只在构造 `Repl` 之前使用，留在栈上）；`TurnCtx` 由 `Repl::turn_ctx(&self, send_overlay)` 构造；六个从参数收 `cancel` 的命令（`/file` `/edit` `/model` `/export` `/debug` `/skills`，实参都是 `root_cancel`）改为读 `repl.cancel`，与其余命令一致；`cmd_model` 的 `overlay` 参数和 `cmd_skills` 的 `overlay`/`root`/`home` 参数都改从 `repl` 取；`compact_now(.., declined: &mut u64)` 改读 `repl.compact_declined`；overlay 的按消息刷新（`refresh_overlay`）、`title_now`、`join_title` 变成 `Repl` 的方法。构造 `Repl` 之后，`run()` 的栈上只剩主循环本身。

行为边界：无。`root_cancel` 与 `repl.cancel` 本就是同一个 token 的两条路。

## C 片（暂缓）：`TurnEngine` 方法化

报告建议把 `run_turn` / `tool_loop` / `walk` 变成一个拥有 `ctxm`、`steer` 的 `TurnEngine` 的方法。暂缓的原因是借用形状：`run_turn` 同时需要 `&mut history`、`&mut ctxm`、`&mut steer` 与 `&provider`，而 `history`、`ctxm` 又被十来个命令直接读写。把它们收进引擎后，要么命令改经 `repl.engine.ctxm` 访问（换个名字的同一件事），要么方法内部仍要拆字段借用。B 片做完后再看 `Repl` 上还剩多少散落状态，届时决定是否值得。
