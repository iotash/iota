# 5.2-1 `ProviderError` 停止擦除 `LlmError`

对应 `ARCH-REVIEW.md` F1。目标：provider 边界保留 wire 错误的类型，chat/repl 层用 `match` 分类，不再沿 `source()` 链 downcast；用户可见文本逐字节不变。

## 形状

```rust
pub enum WireOp { Chat, Stream, ListModels, Raw }   // prefix(): "chat error: " | "stream error: " | "failed to list models: " | ""

pub enum ProviderError {
    #[error("{}{source}", .op.prefix())]
    Wire { op: WireOp, #[source] source: LlmError },
    NoChoices,
    Permanent(PermanentError),
    Cancelled,
    #[error("{0}")] Other(#[source] BoxError),      // 无 wire 类型的原样透传（图片结果拉取失败）
}
ProviderError::wire(op, e)   // LlmError::Cancelled → Cancelled，其余 → Wire
ProviderError::llm(&self)    // Wire 的 source
```

`map_llm_err(e, ProviderError::Stream)` 的 23 处调用点变成 `ProviderError::wire(WireOp::Stream, e)`；图片 dialect 的 `map_llm_err(e, Other)` 变成 `wire(WireOp::Raw, e)`，Display 仍无前缀。

## 消费者

- `describe_error(&ChatError)`：`Provider(Wire { source, .. })` 走 `describe_llm`（Status 表 / no-events / network），其余一律 `ErrorReport::request_failed(text)`。`UiError` 走后者。
- `is_retryable(&ChatError)`：`Wire { source }` 上 `match`——`NoEvents | Cancelled → false`，`Status(se) → 429 || >= 500`，其余 `true`；`Cancelled | Permanent → false`；非 provider 错误 `true`。删除 `has_non_429_4xx`。

## 有意的行为边界

- 4xx 字符串扫描删除。它只对「文本里含 4xx 数字」的非 wire 错误起作用：`Other` 只由图片 dialect 产生，而图片 provider 从不自动重试（`allowed=false`）；`Io`/`Child`/`UnknownAgent` 的文本不含状态码。生产路径无差异。
- `PermanentError` 不再被「看穿」。生产中它只经 `PermanentError::msg` 构造（字符串），从未包过 wire 错误；对应测试用例改为「permanent 失败保留其文本」。
- 测试桩改用 `ProviderError::other("boom")` 造假失败：`Chat/Stream(BoxError)` 曾允许任意文本，`Wire` 只接受 `LlmError`。六处 `"stream error: boom"` 断言改为 `"boom"`；`FakeProvider` 的模型列表失败通知从 `Fetching models failed: failed to list models: …` 变为 `Fetching models failed: …`（只是桩的文本，真实 wire 错误的双前缀由 `tests/cmd/cli.rs` 经 mock server 继续钉住）。
- 需要「不可重试的 4xx」的测试改为构造真实的 `LlmError::Status(400)`，而不是含 "400" 的文本。
